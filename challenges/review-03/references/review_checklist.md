# 审查清单（review-03 / 研究方法与统计审查）

版本 1.0.0。本文件是**唯一权威的检查项定义**：`scripts/main.py` 中每条规则 ID 与本节 ID 一一对应；
未在代码中自动实现的条目在 `checks{}` 里标 `manual`，由 Agent 在阶段 2 阅读全文后判定，不允许留空。

## 0. 两套坐标：六类审查面 × 五个检查面

题面要求同时覆盖两套分类，`issues[]` 的每条记录同时携带两个标签：

| 字段 | 取值 | 含义 |
|-|-|-|
| `category` | `fact` / `citation` / `design` / `statistics` / `logic` / `norms` | 六类审查面（题面 2 节「任务完成度」） |
| `facet` | `design` / `variables` / `statistics` / `sample_size` / `reporting` | 五个检查面（题面 1 节「突破方向」） |

映射关系不是一一对应：`design` 类问题可能落在 `design` 或 `variables` 面，`statistics` 类问题可能落在
`statistics`、`sample_size` 或 `reporting` 面。五面覆盖度由 `summary.facet_coverage` 单独统计。

## 1. 严重度定义（先定性质，再定级别）

| severity | 判定条件（满足任一即适用） | 作者必须做什么 |
|-|-|-|
| `blocker` | 结论不可复核或不可解释：关键统计量缺失导致主结论无法验证；数据与结论方向相反；样本量/分组与结论矛盾 | 补数据或改写结论，否则不可发表 |
| `major` | 方法学缺陷会改变结论方向或效度：设计与研究问题不匹配、检验方法与数据结构不匹配、多重比较未校正、样本量依据缺失、效应量与置信区间缺失、无伦理声明（人体/动物研究） | 必须修回并说明 |
| `minor` | 报告不完整但结论方向大概率不变：仅给不等式 p 值、未报告软件版本、未报告正态性检验、缩略语未定义 | 建议修改，可与编辑协商 |
| `suggestion` | 规范性/可读性改进，不影响效度：报告规范声明、数据可得性、图表呈现方式 | 可选 |

**关键判据（防止一律写成"重大缺陷"）**：
1. 「作者没报告」≠「作者做错了」。缺报告项按 `minor`/`major`（取决于是否影响结论可验证性）计，措辞用
   `未报告`，不得写成 `错误`。
2. 只有当缺陷**会改变结论方向**时才升到 `major`；只有当缺陷使**结论无法验证**时才升到 `blocker`。
3. 需要领域外部信息才能定论（例如"该剂量是否合理"）→ 不判错误，进 `pending_human`。
4. 语言风格、写作偏好、期刊格式细节不属于本题范围（题面明确排除语言润色），不得作为 issue 输出。

## 2. C1 事实核验（category=`fact`）

| ID | 检查问题 | 默认严重度 | 需要的证据 |
|-|-|-|-|
| F-01 | 正文引用的表号/图号在稿件中是否真实存在 | major | 正文引用句 `quote` + 稿件中已定义的表/图编号清单 |
| F-02 | 样本量是否前后一致（摘要/方法/结果/表格/流程图） | major | 两处及以上 `n =` 原句，逐字并列 |
| F-03 | 百分比与所给分子分母是否自洽（`x/y` 与 `p%`） | major | 同一句内的分数与百分比原句 |
| F-04 | 同一统计量在摘要、正文、表格中是否一致 | major | 两处原句 + 各自 locator（`manual`：需跨节比对，代码只做同段落内） |
| F-05 | 数值单位是否缺失或混用（同一指标 mg/g、mmol/L 与 mg/dL） | minor | 含数值的原句 + 单位不一致处 |

|-|-|-|-|

| S-13 | 相关/回归是否报告变量筛选方式与前提检验 | minor | 方法节原文（`manual`） |
| S-14 | p 值格式是否规范（`p = 0.000`、`P<.0001`） | suggestion | 原句 |
| S-15 | 是否报告精确统计量与自由度（t/χ²/F 值 + df） | minor | 统计表述原句 |

## 8. `checks{}` 的六类状态机

每个 category 必须给出：`status` ∈ `checked` / `partially_checked` / `not_applicable` / `not_checked`，
并附 `scope`（实际读到的范围）、`items`（条目级结果）、`findings`（issue id 列表）、`open`（未决项）。

- `not_applicable` 必须给 `reason`（例：稿件无参考文献表 ⇒ C2 部分不适用，但 C-05 本身仍成立）。
- 任何 `not_checked` 必须同时写入 `uncertainty[]`，说明缺什么材料才能检查。
- 六类中不得有缺席的键——缺失键按"漏检"计分。

## 9. 五个检查面的覆盖判据 `summary.facet_coverage`

`covered`（该面至少 1 条 issue 或 1 条显式"已检查且未发现问题"记录）/ `partial` / `not_covered`。
即使该面无缺陷，也必须在 `checks[category].items[]` 里留下 `status="pass"` 的条目记录，
否则视为漏检。

## 10. 使用规范依据（可引用名称，不得编造 DOI/页码）

允许在 `reason` 中引用下列规范的名称与年份（通用知识，不需要联网核对）：
CONSORT 2010、STROBE、PRISMA 2020、ARRIVE 2.0、CARE、ICMJE Recommendations、APA 7th、
SAMPL Guidelines、EQUATOR Network。**禁止**给出未在稿件中出现且未经核实的文献编号、DOI、页码。
