# Research Library Curator（科研资料库落库与版本管理）

## 0. Objective and rubric priority

This Skill must produce a complete, verifiable research library under `/app/output/library`, not advice about how to do it. High scores come from four things:

1. **Actually moving/copying files into a rule-driven directory tree** with a complete inventory.
2. **Metadata records with per-field provenance** — no field value without a source locator.
3. **Content-hash deduplication and version chains** — not filename-based guesses.
4. **Honest result.json + logs** that another person or agent can rerun and compare.

Priority order under the official rubric: actual effect 40 > use gain 25 > innovation 15 > reliability 10 > ecosystem 10. Spend effort accordingly.

---

## 1. Hard invariants

These rules cannot be broken by the Agent or by scripts.

1. **Read-only input.** Never modify, move, delete, or rewrite anything in `/input` or its subdirectories.
2. **Always exit 0.** Scripts and Agent both finish with exit code 0. Problems go into `errors`, `degradations`, `pending_human`, or `failures`.
3. **No fabricated scientific data.** If a field cannot be read from a real file, companion table, filename, or case note, it is `null` or `[]` with an entry in `gaps` or `pending_human`.
4. **No hand-editing structured JSON generated by scripts.** `claims.json`, `evidence_table.json`, `result.json`, `version_chain.json`, and similar structured outputs must be produced or overwritten by scripts. Agent judgment goes into `agent_review.json`, `work/draft.json`, textual reports, or `pending_human.json`.
5. **Every material assertion in narrative reports must carry a `[S#]` source reference and a locator**, such as `[S3] inventory.csv#row=12` or `[S1] metadata.csv#locator=content:offset=823`.
6. **Do not report missing work as completed.** If a contract field cannot be satisfied, mark `status=partial`, `status=insufficient_evidence`, or `status=input_error`.
7. **Do not invent benchmarks, golden standards, or platform scores.** The platform records those. This Skill only records its own measurements, gaps, degradations, and evidence.

## 3. Single-command workflow

The preferred entry point is:

`python3 -B scripts/main.py run --input /input --output /app/output --work /app/work`

This one command runs three stages internally:

### Stage 1: init

- Recursively scan `/input`.
- Read `case.json` and `task.md`.
- Produce a source manifest: every material file gets `source_id` such as `S1`, `S2`, `S3`.
- Record size, `sha256`, readable extension, MIME/type sniff, permission status, path, and mtime.
- Extract candidate fields: filename-derived year, project code, version label, DOI candidate, instrument candidate, companion-table keys, and text snippets with offsets.
- Group obvious exact duplicates by content hash.
- Group potential version candidates by normalized base key after removing copy/version markers.
- Write an init ledger to `/app/work/init_ledger.json`.

### Stage 2: build

- If `/app/work/draft.json` exists, use it as the Agent judgment layer.
- If `/app/work/draft.json` does **not** exist, run deterministic extraction:
  - Every assigned value must carry a verbatim `quote` and a `locator`.
  - Record `"extraction_mode": "AUTO_EXTRACT"` in `degradations` and `gaps`.
  - Write `/app/work/draft.auto.json` as the fallback working draft.
- Validate that every proposed claim has a real source and locator.
- Create `/app/output/library/` with real copied files:
  - Preserve original content; never overwrite.
  - Recompute sha256 after copy.
  - Handle same-name different-content files with `__altN`.
- Generate:
  - `inventory.csv`
  - `metadata.csv`
  - `version_chain.json`
  - `duplicates.json`
  - `directory_tree.txt`
  - `operations.log`
  - `report.md`
  - `run_manifest.json`
  - `verify_report.json`
  - `pending_human.json`
  - `agent_review.json`
  - `selftest_report.md`
- Finalize `result.json`.

### Stage 3: selfcheck

- Check all `/app/output` files exist.
- Check `result.json` parses as valid JSON.
- Check every key in the original `output_contract` appears at top level and in nested `output_contract`.
- Check `case_id` matches `/input/case.json`.
- Check `run_manifest.json` hashes match actual generated files.
- Check the library copy count matches inventory copy records.
- Check no source file in `/input` was modified.
- Write `selftest_report.md`.
- Rewrite `result.json` once as final state.
- Exit 0.

## 4. Agent-first dual path

The Agent is the primary quality layer when budget allows. The deterministic fallback ensures the package still produces a complete real result when the Agent cannot or does not write a draft.

### Path A: Agent path

Use this path when the Agent can read the case and materials.

1. Run init separately if available:
   - `python3 -B scripts/main.py init --input /input --output /app/output --work /app/work`
   - Legacy fallback: run the full `run` command once and inspect `/app/work/init_ledger.json`.
2. Read `/input/case.json` and `/input/task.md`.
3. Read the source manifest and inspect files with `.pdf`, `.docx`, `.csv`, `.tsv`, `.json`, or text-like extensions.
4. Read actual content from the highest-value files: those affecting metadata, deduplication, version chains, query answers, or contract fields.
5. Write `/app/work/draft.json`. This file contains Agent judgments in shape:
   - `case_id`
   - `method`: `"agent_read"` or `"agent_read_plus_script"`
   - `fields`: array of `{ "field", "value", "source_id", "file", "locator", "quote", "confidence", "reason" }`
   - `duplicates`: array of confirmed/excluded duplicate groups
   - `versions`: array of ordered version chains with rationale
   - `uncertain`: array of unresolved items
6. Run the build/check flow:
   - `python3 -B scripts/main.py build --input /input --output /app/output --work /app/work`
   - `python3 -B scripts/main.py check --input /input --output /app/output --work /app/work`
   - If subcommands are unavailable, rerun full `run` after draft exists.
7. Improve textual final deliverables:
   - `report.md`
   - `agent_review.json`
   - `pending_human.json` additions
   - Never hand-edit structured script output.
8. Run selfcheck and confirm final `result.json`.

### Path B: Deterministic fallback

If no `/app/work/draft.json` exists at build time:

- The script builds a complete working draft by deterministic extraction.
- It records `AUTO_EXTRACT` in:
  - `result.json.degradations`
  - `result.json.gaps`
  - `agent_review.json.automation_note`
- It still produces the same full deliverable set.
- The resulting library is real; metadata values may be lower confidence but are never fabricated.
- This path costs few model requests and is the budget-safe baseline.

Both paths must produce the same file set and the same `result.json` contract schema.

Example contract fields might include directory tree, file inventory, metadata, version relations, duplicates, archive manifest, queries, report, pending issues, sources, or any other requested field. Map them by key name to the corresponding artifact. If a contract field cannot be satisfied, use `null`, `[]`, or `{}` as appropriate and record it in `contract_unresolved`.

- `case_id`
- `status`
- `output_contract`
- `inventory`
- `directory`
- `metadata`
- `versions`
- `duplicates`
- `operations`
- `failures`
- `queries`
- `report`
- `metrics`
- `sources`
- `uncertainty`
- `pending_human`
- `errors`
- `degradations`
- `changes`
- `runtime`
- `verification`

`status` values:

## 6. Inventory, metadata, and provenance rules

### 6.1 Inventory and hashing

For every source file:

- `source_id`: stable within run, e.g. `S1`, `S2`, `S3`.
- `filename`: original basename.
- `path`: original relative path under `/input`.
- `size_bytes`.
- `sha256`: streamed hash of actual file bytes.
- `readable`: `yes`, `permission_denied`, `corrupt`, `unsupported_encoding`, `no_text_layer`, or `skipped_too_large`.
- `file_type`: sniffed by magic bytes or extension where unavoidable.
- `action`: `copied`, `reuse`, `exact_duplicate`, `alt_version`, `name_conflict`, `skipped_permission`, `skipped_corrupt`, `skipped_too_large`.
- `destination`: final path under `/app/output/library` if copied.

Unreadable files must still appear in inventory, not vanish.

### 6.2 Metadata field extraction

Prefer evidence in this order:

1. Companion table under `/input`, if present: CSV, TSV, or JSON list with `file`, `name`, or `path` key.
2. File content where extractable.
3. Filename rules: year, project code, version label.
4. File system mtime for reference only, never as a primary publication year.
5. Case or task note administrative statements.

Supported fields:

| Field | Main sources | Source label |
|---|---|---|
| `title` | companion table, content first heading | `companion_table`, `content` |
| `authors` | companion table, content | `companion_table`, `content` |
| `year` | filename four-digit year outside project code, companion table | `filename`, `companion_table` |
| `mtime_year` | filesystem mtime year | `derived` |
| `project` | companion table, filename code | `companion_table`, `filename` |
| `project_code` | filename regex, companion table | `filename`, `companion_table` |
| `instrument` | filename, content instrument word list | `filename`, `content` |
| `doi` | content regex `10.\d{4,9}/…`, filename | `content`, `filename` |
| `version_label` | filename markers such as `v3`, `final`, `定稿`, `修订`, `copy`, `(1)` | `filename` |
| `data_type` | companion table, extension inference | `companion_table`, `derived` |
| `notes` | case/task admin notes or alias notes | `admin_note` |

Every value in `metadata.csv` must have a locator. For example:

- `inventory.csv#row=17`
- `content:offset=823`
- `filename#regex:year`
- `artifacts/notes.csv#row=4`
- `$.admin_notes`

If no source exists, value is `null` and the field is listed in `gaps` or `pending_human`.

### 6.3 Content-based deduplication

- Same `sha256` = exact duplicate.
- Keep the most informative copy: prefer non-`copy`, shortest canonical name, earliest stable path.
- Other exact duplicates get `action=exact_duplicate`.
- Exact duplicates are not copied twice.
- Same canonical name but different sha256 = `__altN` suffix, no overwrite.

### 6.4 Version chain rules

- Do **not** chain by filename alone.
- Remove version markers and copy markers to compute `base_key`.
- Same `base_key` and same extension group can form a version chain only if multiple different content hashes exist.
- Sort chain candidates by `(mtime, version_label_rank, filename)`.
- Record:
  - `current_version`
  - `supersedes`
  - `superseded_by`
  - `diff_vs_previous`
- `diff_vs_previous` may be text line additions/deletions or byte-size difference when no text layer is available.
- If relationship cannot be determined, do not invent a chain; mark pending.

Version label rank examples:

- `draft` < `rev` < `v1` < `v2` < `v3` < `final` < `定稿`
- If rank is uncertain, use mtime and record `version_confidence=medium`.

## 7. Directory placement and naming

Target layout:

`library/<project>/<year>/<category>/<canonical_name>`

| Component | Rule |
|---|---|
| `project` | Use `project_code` or `project`; fallback `_unassigned`. |
| `year` | Only use 1900–2100 four-digit year from filename or companion table; fallback `_undated`. Do not use mtime year as directory year. |
| `category` | `01_literature`, `02_documents`, `03_tables`, `04_figures`, `05_code`, `06_archives`, `07_other`. |
| `canonical_name` | NFC normalize; replace control characters and `<>:"/\\|?*` with `-`; collapse whitespace; max 120 chars; keep extension. |

Original filenames are always retained in `inventory.csv` as `filename`.

## 8. Archive, retrieval, and queries

If the contract requests an archive or knowledge structure:

- Generate `archive_manifest.json` or `archive_manifest.csv` as required.
- If an archive package is requested, create a real archive under `/app/output`, then recompute its sha256.
- `queries[]` are lexical by default over filenames, paths, metadata fields, and extracted text.
- Record query method as `lexical`.
- If a question cannot be answered from real extracted content, answer with `"unanswerable_from_materials": true` and list the missing evidence.

## 9. Conflict, failure, and recovery handling

| Situation | Action |
|---|---|
| Permission denied | Include in inventory with `readable=permission_denied`; add to `failures`; do not silently skip. |
| Corrupt file | Include source entry, record `readable=corrupt`; attempt no interpretation. |
| Unsupported encoding | Record `unsupported_encoding`; if alternative UTF-8/GB18030/Big5 read works, use it and note the conversion. |
| PDF without text layer | Record `no_text_layer`; do not OCR unless a tool is explicitly available; otherwise mark pending. |
| Same name different content | Copy as `__altN`; set `integrity_flag=name_conflict`. |
| Same content different names | Deduplicate by sha256; keep one physical copy; list aliases. |
| Hash mismatch after copy | Delete incomplete destination copy; mark `hash_mismatch_after_copy`; retry once; if still failing, leave pending. |
| Missing companion table row | Do not fill from guess; leave `null` and add pending. |
| Missing contract field | Use `null`/`[]`/`{}`; add `contract_unresolved`; never delete the field. |
| Empty `/input` | Produce valid `result.json` with `status=insufficient_evidence`; include empty inventory. |
| Missing `case.json` | Search for `case*.json`; if none, use `case_id=_unknown` and `status=input_error`. |
| Low disk space or copy failure | Record `errors`; return `status=partial`; preserve already produced artifacts. |

## 10. Evidence, sources, and verifiability

Every major output needs a source reference:

- `[S2]` = source manifest id.
- `inventory.csv#row=8` = row locator.
- `metadata.csv#locator=content:offset=101` = field locator.
- `operations.log#seq=12` = operation locator.
- `directory_tree.txt#path=library/PROJ/2023/...` = placement locator.

`run_manifest.json` must contain:

- `run_id`
- `run_timestamp`
- `case_id`
- `input_sha256_set`
- `script_version`
- `python_version`
- `output_files`: list of filename, size, sha256
- `reproducibility_note`

Re-run behavior:

- Same input should produce the same sorted inventory, same hash set, and same library tree.
- Already copied files are reused, not duplicated.
- Operations log reflects `action=reuse` and `copied=0` on a clean rerun.

## 13. Hidden-case robustness

### Normal hidden cases

- A collection with PDFs, DOCX, CSV/TSV, figures, code, archives, and notes.
- Expect duplicates and versions.
- Job: prove real placement, metadata, deduplication, version chains, and a handoff report.
- Success: full library tree, inventory/metadata with sources, operational log, run manifest, queries answered, honest gaps.

### Boundary hidden cases

- Chinese and special-character filenames.
- Deep directory nesting.
- Large files, many files, or very small empty files.
- Same-name different-content files.
- Same-content different-name files.
- Repeated runs over the same input.
- Success: no oversimplified fallback; special names are preserved in inventory, canonicalized only in library names; no overwrite; stable rerun behavior; large-file problems recorded, not hidden.

### Abnormal hidden cases

- Missing or malformed `case.json`.
- Empty `/input`.
- Unreadable directories, permission errors.
- Corrupt PDF/DOCX/ZIP.
- Unsupported encoding.
- Very low disk space.
- Success: valid `result.json` with honest `status`; non-zero findings recorded in errors; exit 0; no crash; partial outputs preserved.

## 16. Final completion standard

A complete run must demonstrate three things:

1. **The library is real.** Files are physically present under `/app/output/library`, not just named in a suggestion.
2. **The evidence is real.** Inventory, metadata, versions, duplicate records, operations, and reports can be traced to actual source files and locators.
3. **The limits are real.** Every skipped file, missing field, conflict, uncertainty, or failed check is visible in result.json and supporting artifacts.

If a field cannot be completed truthfully, the Skill should say so clearly and still deliver a valid, scrutinizable partial result. That is the highest-scoring behavior under this task.
