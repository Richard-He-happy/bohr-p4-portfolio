# 开题报告模板与检查表（plan-template.md）

本文件是 `scripts/render.py` 的数据源，同时是人工可读的模板。上半部分是七要素检查表与判据，下半部分是 `<!-- KEY:... -->` 标记的机器读取块，被兜底稿与成稿表格复用。修改本文件即可改模板文字，无需改代码。

## 1. 七要素检查表（成稿必须逐项落地）

| 要素 | 必须写清 | 不合格的典型表现 |
|---|---|---|
| 背景与缺口 | 已知—未知—待验证三段，缺口由材料证据指向 | 把相关领域综述一遍，缺口与本研究无因果关联 |
| 研究问题 | 1–3 条，每条含假设与"何种观测会否定它" | 只写"探索/研究 X"，无法被数据否定 |
| 研究目标 | 与 RQ 一一对应，含指标、样本、对照、时点 | 目标与问题各写各的 |
| 技术路线 | 步骤化：输入→操作→输出→依赖，方法来自材料 | 方法泛泛而谈，步骤间无依赖 |
| 阶段计划 | 落在给定周期内，里程碑有可检查判据与关键路径 | 里程碑只写月份，无交付物与判据 |
| 风险 | 数据/方法/进度/伦理四类，含触发信号、影响、备选、决策时点 | 只写"存在一定风险" |
| 预期成果 | 与 RQ 对应，写清验证方式与判据 | 把设想写成已获结果 |

## 2. 证据规范

- 每条关键论断带 `source_id`（材料编号，如 `M1`）、`locator`（`p3` = 该材料第 3 段）、逐字 `quote`。
- `quote` 必须能在原文逐字找到（脚本按去空白归一化比对）；找不到则降级为提醒并进 `pending_human`，**不得改写原文凑通过**。
- 数字、单位、样本量、周期口径必须与材料同形；计划新增的目标值须标为"计划值"并给依据。

## 3. 状态判定（脚本自动给出）

| status | 条件 |
|---|---|
| ok | 七要素齐全、RQ 有判伪条件与阈值、里程碑≥3、风险≥4 且≥3 类、引文命中率≥90%、工作稿来自 Agent |
| partial | 上述任一不满足，或使用了兜底模板，或存在要素错误 |
| insufficient_evidence | 材料存在但无可解析文本 |
| input_error | 未找到任何输入材料 |
