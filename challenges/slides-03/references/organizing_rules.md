# 汇报组织规则：听众 → 结构 → 每页 → 问答

本文件是 `SKILL.md` 第 5 节的展开，给出可直接套用的取舍规则。所有规则都以"页面上的断言能在源材料找到位置"为前提。

## 1. 听众与场合决定背景比例

| 听众/场合 | 背景页 | 方法深度 | 结果呈现 | 结论强度 |
|-|-|-|-|-|
| 课题组组会 | 0–1 页 | 机制、超参、失败点 | 进度与对比，含未完成项 | 保守，明说风险 |
| 学位答辩/评审 | 1 页（问题价值） | 创新点 + 与基线差异 | 主结果 + 消融 + 显著性 | 与证据等级一致 |
| 跨领域听众 | 2 页 | 只讲输入输出与直觉 | 一个关键数字 | 不夸大外推 |
| 合作方/工程落地 | 0 页 | 接口、成本、依赖 | 时延/资源/失败率 | 给适用条件 |

术语只解释听众可能不懂的；同领域听众用术语反而更快。

## 2. 时长 → 页数 → 每页字数

- 1 页 ≈ 1.2–1.5 分钟（含切换与停顿）；12 分钟 ≈ 8 页，20 分钟 ≈ 13–15 页。
- 每页 3–5 条要点，每条 ≤ 25 字（中文）/ ≤ 14 词（英文）；超出的内容进 `notes`。
- 预留 1–2 页"备用页"（补充数据、对照、失败案例），放 `qa.backup` 指向的位置。
- 页数要求优先于上述估算：任务给了 8 页就做 8 页，内容不够就补备用页或合并，不要凑页。

## 3. 叙事骨架（不要按论文目录搬）

**通用**：问题（谁受影响）→ 现有做法为什么不够 → 我们的做法（一句话）→ 关键证据（2–3 页）→ 边界与结论 → 下一步。

| 场合 | 骨架变体 |
|-|-|
| 组会进展 | 目标 → 本周做法 → 结果/阻塞 → 下周计划 → 需要的帮助 |
| 答辩 | 问题价值 → 创新点（与最近工作对比）→ 方法 → 主结果+消融 → 边界 → 贡献总结 |
| 评审 | 结论先行 → 证据链（每页一条证据）→ 证据强度与不确定性 → 建议 |

每页只回答一个问题；页标题写该问题的答案（结论句式）。

## 4. 页级检查（写完逐页过一遍）

1. 页标题是不是结论？改成"现象/数字 + 判断"。
2. 3–5 条要点，是否都在支撑同一个 `claim`？有一条跑题就拆页或删。
3. 每条要点有 `locator`；`quote` 逐字可查。
4. 数字是否与源材料一致（同一数字跨页口径一致）；是否标了样本量/条件。
5. `evidence_strength` 与证据匹配：单数据集、单模型、无对照 → `moderate` 以下。
6. `notes` 是否提供了页面之外的信息（讲法、条件、常见误解、被追问的第一句回答）。
7. 图表引用是否指向材料中真实存在的图/表；材料没图就写"无（材料未提供）"，不要臆造图注。

## 5. 问答准备（每题都要能落到页）

- 机制类："为什么这样做有效？" → 回答给机制链条，`backup` 指向方法页或消融页。
- 数据类："样本量/划分/泄漏？" → 给数字与出处，`backup` 指向数据页。
- 对照类："与 X 方法比呢？" → 只给材料里有的对比；没有就直说"未做，属下一步"。
- 局限类："什么时候会失败？" → 主动给失效条件，`backup` 指向限制页。
- 至少 2 条，最多 6 条；答案与页面口径必须一致（同一数字不同说法是最常见的扣分点）。

## 6. 已知限制

- locator 精度取决于源材料结构：PDF 依赖 `pdftotext` 的段落切分，扫描件（无文字层）只能列为缺口。
- 图/表内容不做像素级读取：只做"引用绑定"（指向图号/表号/段落），不重绘数据。
- 模板继承保留母版/版式/主题/字体，但重建幻灯片：模板里的自定义占位符动画、SmartArt 不保留。
- 预览 PDF 的版式等价性依赖 LibreOffice；无 LibreOffice 时为文本版预览，需桌面端复核。
- 脚本不判断科学正确性，只保证"页面断言 ↔ 源材料位置"的对应关系成立。
