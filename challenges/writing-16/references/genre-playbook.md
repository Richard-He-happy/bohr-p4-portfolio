# 受众 × 体裁手册（改写策略与强度词表）

用于 `draft.json` 的 `audience`/`genre` 填写与正文取舍。三张表 + 一组词表 + 反模式。

## 1. 受众画像（先定解释深度，再定篇幅）

| 受众 | 知识背景 | 阅读目的 | 解释深度 | 术语策略 | 例子 | 篇幅基准 |
|---|---|---|---|---|---|---|
| 产业界（企业/投资） | 有工程或商业背景，无本领域实验经验 | 能否落地、代价、风险 | 一层因果 + 关键指标 | 保留 3–5 个术语，首次展开；其余换通名 | 用"相当于/对比基线"类比 | 800–1500 字 |
| 基金/项目评审 | 同领域或邻近领域专家 | 创新性、可行性、证据强度 | 方法要点 + 证据链 | 可用领域术语，缩写首展 | 不需要类比 | 1000–2000 字 |
| 政策/管理部门 | 非技术背景，关注影响面 | 影响、风险、监管需求 | 结论 + 条件 + 边界 | 全部换通俗说法，缩写不用 | 场景化类比 | 600–1200 字 |
| 非专业公众 | 无专业训练 | 与自身相关性与意义 | 只给结论与一个机制比喻 | 不出现缩写，或首次即全称+比喻 | 生活化类比，禁用夸张 | 500–1200 字 |
| 同行（论文摘要/技术报告） | 同领域 | 方法可复现性、结果可靠性 | 完整方法要点与统计口径 | 标准术语，缩写首展 | 无 | 按期刊/模板 |

## 2. 体裁结构模板

| 体裁 | 必备结构 | 论断强度处理 | 禁忌 |
|---|---|---|---|
| 技术转化简报 | 一句话结论 → 问题 → 方案要点 → 关键数据（含条件）→ 落地条件/风险 → 待验证 | 初步结果标"初步"；应用前景单列"待验证" | 把体外/小样本结果写成"已实现" |
| 项目申报摘要 | 需求 → 目标 → 路线 → 前期结果 → 创新点 → 计划 | 创新点须对应已有数据；计划与结果分开写 | 把计划写成已完成的成果 |
| 科普文章 | 现象切入 → 机制比喻 → 证据（1–2 个数字）→ 局限 → 意义 | 一律降一档：`established`→"研究发现"；`preliminary`→"初步显示" | 用"治愈/彻底解决/突破" |
| 论文摘要 | 背景 → 方法 → 结果（含 n 与统计）→ 结论 | 与原文同级，不改限定语 | 删掉样本量与统计口径 |
| 政策简报 | 结论 → 影响面 → 条件与风险 → 建议 | 建议与证据分列，建议标"建议" | 把建议写成既成事实 |

## 3. 取舍决策（压缩时按此顺序丢）

1. 先删：致谢、投稿与基金编号、重复表述、与读者无关的推导、文献罗列。
2. 再压：方法参数、仪器型号、试剂批号 → 压成一句"方法概要"。
3. 最后才动：样本量与分组、剂量/时长/平台、比较基准、统计口径 → **只允许压缩表达，不允许删除**。
4. 绝不动：主结论、关键数字与单位、局限与不确定性、图表编号（无编号则注明"原文未给编号"）。

判定标准：删掉后读者是否还能判断"这个结论在什么条件下成立"。不能 → 不是冗余，是证据。

## 4. 论断强度词表（转写时降级，不得升级）

| 源文表述 | 级别 | 允许的转写 | 禁止的转写 |
|---|---|---|---|
| 显著提高/证明/表明（有统计检验） | established | "研究发现…（p<0.05，n=48）" | "彻底解决" |
| 提示/初步/在体外模型中 | preliminary | "初步结果显示…，尚需体内验证" | "已证实有效" |
| 可能/推测/机制上 | hypothesis | "研究者推测…，机制尚未验证" | "因为…所以…"（因果断言） |
| 有望/具备潜力 | 商业外推 | 保留"有望"，并进 `pending_human` | "将带来…市场"（无源数据） |

同义收敛：全文对同一对象只用一种说法（如统一用"删除率"，不混用"编辑效率/纠错率"）；首次出现给英文原名。

## 5. 常见失败与处置

| 失败 | 症状 | 处置 |
|---|---|---|
| 事实漂移 | 数字近似化、单位缺失、样本量丢失 | 回原文核对，进 `preserved` 逐字锁定 |
| 受众错配 | 公众稿出现缩写墙/公式；申报稿过于通俗 | 按第 1 表重设解释深度与术语策略 |
| 强度升级 | 初步→已证实；相关→因果 | 按第 4 表降级，并写 `uncertainty` |
| 提纲冒充成稿 | 只有小标题与要点 | `check` 报 `too_short`；补写正文段落 |
| 对照缺失 | 有正文无 `map` | 逐段补 `map`，至少覆盖 P0 内容 |
| 前景注水 | 出现源文没有的市场/成本/时间表 | 删除或移入 `pending_human` |

## 6. 交付前 60 秒复核

- 首段能否让目标读者说出"这跟我有什么关系"？
- 每个数字后面是否带单位与条件？每个结论是否带限定语？
- 全文缩写是否都展开过一次？同一概念是否只有一种说法？
- `map` 是否覆盖了所有关键结论段？`changes` 是否覆盖了每处删改？
- 有没有一句话是源材料里找不到依据的？（有则删或进 `pending`）
