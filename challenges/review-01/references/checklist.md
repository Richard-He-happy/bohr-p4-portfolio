# 审查清单、判定锚点与 agent findings 协议

本文件供人类审稿人与审查 Agent 共用：清单用于逐项执行，锚点用于统一分级，协议用于把语义级发现
并入脚本产出的结构化结果。规则化检查项与阈值以 `rules.json` 为准，本文件说明“怎么判、何时不判”。

## 1. 执行顺序（每篇稿件固定）

1. 识别稿件版本：`result.json.sources[].sha256` 记录指纹；多份材料时先确定“主稿件”，其余为附件。
2. 确认结构：是否检出章节标题。若未检出（节选、扫描件、单段材料），章节类检查一律标 `not_checked`。
3. 先跑规则（`scripts/review.py`），得到确定性条目；再读 `corpus.json` 做语义补充。
4. 语义补充写入 `agent_findings.json` 后重跑脚本；脚本做逐字校验、去重、编号。
5. 交付前核对 `metrics.quotes_rejected` 与 `pending_human` 是否一致。

## 2. 六类检查项与判定要点

### 2.1 事实与数值一致性（fact_check）
- 样本量：摘要/方法/结果/图表中的 n 是否一致；有无“纳入 N、分析 M”的说明。
- 图表：正文引用的图/表编号是否都有对应图注；编号跳号；图注存在但正文未引用。
- 数值：摘要数值能否在正文找到同值；百分比构成比是否≤100%；单位与量纲是否一致。
- 占位符：TODO/TBD/XX/待补/图 X 等未定稿标记。
- 判定要点：能定位到两处原文并直接对比 → `error`；只有一处且需作者补材料 → `insufficient_evidence`。

### 2.2 引用与论断支持（citation_support）
- 编号越界：正文最大编号 > 文献表最大编号（可确证）。
- 有引用无文献表；文献表条目未被引用；重复条目；缺出版年；DOI 格式异常；未来年份。
- 论断与引文匹配：转述他人结论的句子是否带引文标记；引文是否支持该句主张（需读文献表与上下文）。
- 判定要点：编号类为 `error`；“引文是否支持主张”多为 `insufficient_evidence`，须写明被引文献主张与本文论断的对应关系。

### 2.3 方法设计与可复现性（method_design）
- 对照：是否有对照组/比较组、类型与匹配方式。
- 样本量：各组 n、样本量估算依据、剔除与缺失。
- 随机化与盲法：序列产生方式、分配隐藏、盲的层级与被盲对象。
- 重复：技术重复与生物学重复次数、独立实验批次（体外）。
- 统计方法：软件与版本、检验选择依据、多重比较校正。
- 纳入/排除标准（人体研究）。
- 判定要点：区分“方法有缺陷”（`major`）与“方法可接受但报告不全”（`minor`）。

### 2.4 统计报告完整性（statistics_report）
- `p = 0.000` 或 `p = 0`：必须改为精确值或 `p < 0.001`。
- 显著性主张是否附检验名称、统计量、自由度、效应量。
- `±` 是否说明 SD/SEM/CI；均值是否缺离散度。
- 相关分析是否给 r/ρ/R²；回归是否给系数与 CI。
- 只报 p 不报区间；阴性结论是否给功效或最小可检测效应。
- 判定要点：数值写法错误 → `error`；报告不全 → `insufficient_evidence`。

### 2.5 论证链与逻辑一致性（argument_chain）
- 因果措辞（cause/导致/引起）是否用于观察性设计；是否有混杂控制与敏感性分析。
- “prove/证实”等确定性措辞是否有统计支持。
- 结论是否逐条回应引言提出的目标/假设；是否外推到数据范围之外（人群、剂量、时程）。
- 讨论是否与既有文献比较；是否说明局限。
- 判定要点：结论强度超出设计 → `major`；表述可选更稳 → `minor`/`info`。

### 2.6 学术规范与可发表性（academic_norms）
- 章节齐备：方法、结果、讨论、结论。
- 声明：伦理批准、知情同意、数据可用性、利益冲突、资助、作者贡献。
- 摘要长度、关键词数量、标题长度、编号连续性。
- 判定要点：投稿硬性缺项（伦理、参考文献）→ `major`；常规要件 → `minor`；格式建议 → `info`。

## 3. 严重度锚点

| 级别 | 判据 | 例子 |
|---|---|---|
| `major` | 影响结论可信度、可复现性或构成投稿阻断 | 无对照、n 前后矛盾、p=0、引用编号越界、缺伦理声明、占位符残留 |
| `minor` | 报告不全或规范缺失，可在不补实验的情况下修复 | 随机化方法未说明、± 未标注 SD、缺数据可用性声明、文献重著录 |
| `info` | 改进建议，不影响判定 | 关键词数量、标题偏长、讨论未与文献比较、图表未被正文引用 |

`basis_type` 与严重度独立：同一 `minor` 既可能是 `error`（文献重著录），也可能是 `suggestion`（补局限段落）。

## 4. 误报抑制（必须遵守）

1. **先看适用条件**：非实证材料不触发对照/n/重复/统计类检查；无文献表不触发编号类检查。
2. **不做结构推断**：未检出章节标题时，不得判定“缺少方法章节”；标 `not_checked` 并写原因。
3. **不把惯例当缺陷**：期刊格式、领域写法、作者有意取舍（如 letter 体例省略小标题）只作 `info`，并注明“按目标期刊要求核对”。
4. **不合并不同问题**：同一句有多个缺陷时分别条目，但同一模式同类问题每篇最多 4 条。
5. **不催生结论**：无法判断（图表为图片、补充材料缺失、统计前提未知）→ `pending_human`，写明需要作者提供什么。
6. **quote 必须逐字**：改一个字都算编造；找不到就降级，不得“润色”原文。

## 5. agent_findings.json 协议（语义补充）

脚本默认读取 `<output>/agent_findings.json`（也可 `--merge` 指定）。结构：

```json
{"findings": [
  {"facet": "argument_chain",
   "severity": "major",
   "basis_type": "insufficient_evidence",
   "title": "结论外推到人类患者",
   "quote": "Compound X causes a durable glucose reduction and generalises to human patients.",
   "locator": {"page": 1, "section": "conclusion"},
   "rationale": "仅大鼠 30 例、4 周数据，结论直接外推到人类患者，超出数据支持范围。",
   "suggestion": "限定为“在大鼠模型中”，并说明外推需人体试验验证。",
   "confidence": "high"}
]}
```

字段要求：
- `facet` ∈ `fact_check|citation_support|method_design|statistics_report|argument_chain|academic_norms`（缺失或非法 → 拒收）。
- `quote`：直接从原文复制的连续片段，≥10 字符；脚本按去空白/标点后的全文比对，命中才纳入。
- `severity`：`major|minor|info`（`high/medium/low` 会被映射）。
- `rationale`/`suggestion`：分别写“为什么是问题”和“怎么改”，不得写“建议进一步研究”这类空话。
- `locator`：给出 page/section 有助于人工复核；脚本会以 quote 所在句重算段落与字符区间。
- 拒收原因写入 `pending_human.reason`：`facet_or_quote_invalid`、`locator_failed`。

## 6. 人工复核流程

1. 打开 `issues.csv`，按 `severity` 排序，先处理 `major`。
2. 用 `locator.page / paragraph_id / char_start~char_end` 回到原文，检索 `quote` 原串确认上下文。
3. 对 `basis_type=insufficient_evidence` 的条目，向作者索取缺失材料后再判。
4. `pending_human` 中的条目必须给出处置结论（保留/删除/改写），并记录到 `changes`。
5. 修订稿复审时对比 `sources[].sha256`，确认审的是同一版本。

## 7. 复用建议

- 把 `rules.json` 的 `specs[]` 当作模板：新增检查只需写 `applies` + `fire` + `quote`，无需改代码。
- 用本清单做人工审稿的对照白板：同一稿件分别人工过一遍与跑一遍，统计漏报/误报，即可量化增益。
- 阈值（如摘要 120–420、样本量上限 4 条/模式）集中在 `rules.json` 与本文件，便于按学科调整。
