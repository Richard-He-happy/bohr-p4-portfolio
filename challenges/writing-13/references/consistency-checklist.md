## 1. 数字与口径硬约束（每次运行都复算）

| 约束 | 判据 | 复算方式 |
|-|-|-|
| 七要素齐全 | 立项依据 / 科学问题 / 研究目标 / 研究内容 / 创新点 / 技术路线 / 研究基础与可行性 各有实质正文 | `verify.py` 的 `sections_found` |
| 正文字数 | 约 1600–2600 汉字（以 workorder `draft_size` 为准） | `char_total`（只计中日韩统一表意文字） |
| 目标数 | 恰 3 个，编号 G1/G2/G3 | `goals_count` |
| 计划周期 | 全部时间标记 ≤ 12 月 | `max_month` |
| 规划单位 | 分项之和 = total ≤ 100，且非货币 | `planning_units_total` |
| 风险 | ≥3 条，每条有触发信号 + 备选 | `risks_count` |
| 人工确认 | ≥2 条，须含"真实申请人证据"与"真实资助要求" | `pending_human_count` |

| 无据修饰 | 无"首次/国际领先/填补空白/重大突破"等，或同句有来源 | `banned_unverified` |

## 2. 禁用词表（出现即需同句给 locator，否则删除）

`首次`、`国际领先`、`填补空白`、`重大突破`、`国内外首创`、`世界首创`、`尚无先例`、`领跑全球`、`开创性突破`。
替代写法：`已有研究显示（作者, 年）在 X 条件下达到 Y` + `本申请拟把边界推进到 Z`。

## 3. 归属检查（逐段自问）

1. 这句话里的结果是谁做的？论文结果 → 必须写"外部作者已完成/该文报告"。
2. 这句计划有"拟/计划/将"吗？没有则不能写成已发生。
3. 这句的能力/条件是申请人自有的吗？没有证据 → 写"待补（PH1/PH3）"，不写"已具备"。
4. 这句数字的 locator 在哪？找不到 → 降格为"待核"，进 `pending_human`。

## 4. 评审人视角三问（每段过一遍）

- 凭什么这么写？（有没有 locator 或计划依据）
- 与上一节/下一节的编号对得上吗？（空缺→问题→目标→工作包→里程碑→指标）
- 换一位评审，会不会认为这是承诺而非计划？

<!--BEGIN:risks-->
# 风险与备选方案

> 每条须含可观测的触发信号与可执行的备选方案，并挂到技术路线阶段。

## R1 源条件外推风险（M1–M4）
- 风险：源材料工艺条件与拟开展场景不完全一致，参数外推可能失效。
- 触发信号：M1–M4 重复实验相对偏差超预注册阈值，或关键指标无法复现同一数量级。
- 备选方案：先收缩到同构条件建立基线，再逐因素放宽；启用替代评估指标。

## R2 指标可达性风险（M5–M8）
- 风险：可检验指标或达不到预设口径。
- 触发信号：中期里程碑主要指标完成度低于计划 60%。
- 备选方案：指标降级为"趋势+效应量"报告，并追加一组对照条件。

## R3 可复现性风险（M9–M12）
- 风险：样本量与重复次数不足，结论稳健性受限。
- 触发信号：留出集与训练集指标差异超预设容差。
- 备选方案：增加独立重复批次，改用留一条件交叉验证，完整披露不确定性。
<!--END:risks-->

## 7. 提交前自查顺序

1. `verify.py --output <out>` → `counts.critical` 与 `counts.major` 必须为 0。
2. 手抄一遍矩阵三行，确认与正文编号同名。
3. 搜"首次/国际领先/填补空白"；搜"万元/元"；搜"已具备"。
4. 打开 `result.json` 看 `workorder_execution` 六个布尔量是否全为 true。
